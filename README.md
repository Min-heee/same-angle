# 같은각도

**경과 사진을 찍는 사람이, 지난번 기준 사진과 같은 각도·거리·위치로 찍도록 돕는 웹앱입니다.**

사진 두 장을 나란히 놓았는데 고개가 몇 도만 숙여져 있어도, 달라진 게 변화 때문인지 찍는 조건 때문인지 가릴 수 없습니다.
같은각도는 셔터를 누르기 전에 그 조건을 숫자로 맞춰 줍니다.

> **지금 상태: 만드는 중입니다.** 아래 기능은 설계 문서에 적은 목표이고, 아직 만들지 않았습니다.
> 지금 있는 것은 아이폰에서 카메라가 어떻게 동작하는지 재는 점검 페이지뿐입니다.
> 이걸 먼저 재야 통과 기준과 안내 방식을 정할 수 있어서입니다.

## 어떤 사진에 쓰나

얼굴이 보이는 사진은 얼굴 위치를 찾아 고개 각도를 잽니다. 얼굴이 안 보이는 사진은 각도를 재지 못합니다.

| 사진 | 계획 |
|---|---|
| 정면(고개 수평) | 고개 각도, 거리, 위치를 숫자로 맞춥니다. 맞으면 자동으로 찍습니다 |
| 정면 숙임(헤어라인, 약 30°) | 같은 방식입니다. 숙인 자세에서 측정이 흔들리면 보조 방식으로 내립니다 |
| 좌·우 45° 사선 | 같은 기준으로 아이폰에서 재 본 뒤 정합니다 |
| 정수리 | 고개 각도는 재지 않습니다. 기준 사진 겹쳐 보기, 폰 수평, 밝기가 하얗게 날아갔는지, 흔들림만 봅니다. 셔터는 사람이 누릅니다 |
| 옆머리(90°), 뒤통수·공여부, 수술 직후 가까이 찍는 사진 | 1단계 범위 밖입니다. 다음 단계에서 검토합니다 |

병원마다 찍는 사진 목록이 다릅니다. 실제 병원의 목록은 아직 모릅니다. 그래서 목록을 코드가 아닌 규칙표로 두어 바꿀 수 있게 설계했습니다.

## 할 수 있게 만들려는 것

- 기준 사진을 화면에 겹쳐 띄웁니다.
- 어긋나면 한 번에 하나씩 알려 줍니다. 예: "한 걸음 뒤로", "턱을 살짝 당겨 주세요".
- 얼굴이 보이는 사진은 조건이 맞고 흔들림이 없으면 자동으로 찍습니다.
- 15초가 지나도 맞지 않으면 "그래도 찍기"로 찍을 수 있습니다. 그 사실은 기록에 남습니다.
- 사진마다 "어떤 조건으로 찍었는지" 기록표를 남깁니다.
- 방문이 끝나기 전에 빠진 사진이 있으면 알려 줍니다.

## 믿을 수 있게 하는 장치

- **사진과 영상은 서버로 보내지 않습니다.** 서버가 없습니다. 허용한 곳 말고는 인터넷 요청을 막는 규칙을 코드에 넣었습니다.
  - 단, 처음 켤 때 얼굴 위치를 찾는 파일(약 3.6MB)을 Google 서버에서 받습니다. 이때 폰의 인터넷 주소(IP)가 Google에 전달됩니다.
  - 아이폰에서 실제로 막히는지는 아직 확인 전입니다.
- **애매하면 사람에게 넘기도록 설계했습니다.** 판단이 어려우면 자동으로 찍지 않고 이유를 보여 줍니다.
- **같은 입력이면 늘 같은 결과가 나오도록 설계했습니다.** 정해 둔 규칙으로 판정하고, 통과 기준을 화면에 그대로 보여 줍니다.

## 아직 아닌 것

- **아이폰에서 아직 한 번도 돌려 보지 않았습니다.** 카메라 없는 맥에서만 확인했습니다. 다음 단계는 제 아이폰으로 점검 페이지를 돌리는 것입니다.
- **병원 현장에서 써 보지 않았습니다.** 사용자는 가정한 사람입니다. 시연도 지어낸 데이터로만 할 계획입니다.
- **통과 기준은 아직 확정값이 아닙니다.** 고개 각도 차이 3° 이하 같은 값은 조사로 정한 초깃값입니다. 아이폰에서 재 본 뒤 정합니다.

모발·두피 상태나 치료 효과는 판단하지 않습니다. 찍는 조건만 비교합니다.
의료기기로 허가받은 제품도 아닙니다.

## 다음에 확인할 것

1. **아이폰에서 점검 페이지 돌리기.** 카메라, 얼굴 위치 찾기, 센서가 실제로 어떻게 도는지 잽니다. 지금까지 0회입니다.
2. **밖으로 나가는 요청이 정말 없는지 보기.** 아이폰을 맥에 연결해, 허용하지 않은 인터넷 요청이 0건인지 기록으로 확인합니다.
3. **통과 기준 정하기.** 폰을 손에 들고 찍을 때 숫자가 얼마나 흔들리는지 잽니다. 그걸 보고 3° 기준을 올릴지 정합니다.
4. **촬영 화면 만들기.** 그 결과로 촬영 안내, 자동 촬영(조건이 0.3초 유지되면 찍기), 비교 화면을 만듭니다.

## 누가 만들었나

- 설계 문서와 코드의 초안은 AI 코딩 도구(Claude Code)가 썼습니다. 조사 4건과, AI가 초안의 허점을 따로 찾아보는 검토 4건을 거쳤습니다.
- 무엇을 채택할지와 통과 기준 확정은 제가 합니다. 기준은 아이폰에서 재 본 뒤 정합니다.
- 지금까지 제가 AI 초안을 바꾼 곳은 없습니다(설계 문서 v0.2 기준).
- 자세한 역할 나눔은 [설계 문서](docs/PRD.md) 8절에 있습니다.

### D1 실기기 점검 페이지(`/spike/`)

아이폰 사파리에서 카메라·얼굴 모델·센서·공유가 실제로 어떻게 동작하는지 재는 개발용 페이지입니다.
TECH-NOTES 6절 체크리스트를 섹션 0~11로 나눴고, 섹션마다 해당 항목 번호가 적혀 있습니다.
점검 섹션은 12개(0~11번)이고, 12번은 점검 항목이 아니라 결과 내보내기 화면입니다. 앱이 인터넷에서 받는 외부 파일은 얼굴 모델 1개(약 3.6MB)입니다.

**1. HTTPS 로 엽니다.**
아이폰 카메라는 보안 컨텍스트에서만 열립니다. LAN 의 http 개발 서버로는 안 되고, HTTPS 로 배포한 주소의 `/spike/` 를 엽니다.

**2. 시작 전 준비**

- 자동 잠금 '안 함', 저전력 모드 끔.
- 무음 모드 해제, 볼륨 올림. 기록·카운트다운의 시작과 끝을 삐 소리로 알립니다.
- 0번 [소리 시험]으로 소리가 나는지 먼저 봅니다.
- 사파리 16.4+ 는 오디오 세션을 playback 으로 둡니다. 무음 스위치와 상관없이 소리가 나고, 그 상태를 0번에 적습니다.

**3. 위에서부터 차례로**

1. 환경·소리 시험
2. [카메라 켜기] → [모델 불러오기] → [추론 시작] → [지금 성능 저장]
3. 흔들림 30초 기록
4. 자세 6개
5. 같은 프레임 비교, takePhoto 비교
6. **12번에서 중간 내보내기 한 번**(7·10번은 사파리를 떠납니다)
7. 옛 사진 1장, 동작 센서, 픽셀 비용, 공유 시험, 네트워크 출처

**4. 결과 보내기**

- 결과는 이 기기에 임시 저장됩니다. 탭이 다시 열려도 복원됩니다.
- 마지막 12번에서 [복사](가장 빠름)·[파일로 저장]·[공유] 중 하나로 `same-angle-d1-report-YYYYMMDD-HHmm.json` 을 내보내 개발자에게 보냅니다.
- 개발자는 이 JSON 을 Claude Code 대화에 붙여 넣어 함께 읽습니다.

자세한 순서·완료 조건·내보내기는 TECH-NOTES 10절에 있습니다.

**결과 JSON 에 들어가지 않는 것**

JSON 에는 이미지와 얼굴 랜드마크 좌표가 들어가지 않습니다.
들어가는 것은 기기 정보(userAgent·화면 크기·DPR), 측정 숫자, 자세 픽스처의 행렬 16개 숫자뿐입니다.

내보내기 전에 검사기(`src/core/report.ts`)가 다음을 거부합니다.

- 이미지·랜드마크 키, `data:` URL, base64 로 보이는 긴 연속 문자
- 긴 문자열·배열, 비유한 수
- 섹션마다 수 900개·글자 24,000자를 넘는 총량(여러 조각으로 쪼개 넣어도 걸림)

총량 한도는 통째로 넣는 것을 막을 뿐, 몇 점까지 막는다는 증명은 아닙니다.
나머지는 "섹션 데이터에는 이름 붙인 요약 숫자만" 넣는 점검 페이지 코드가 맡습니다.

### 아직 검증하지 않은 것(세부)

- **점검 페이지를 아이폰에서 아직 돌려 보지 않았습니다.**
  카메라 없는 맥의 크로미움 계열 브라우저에서 다음까지만 확인했습니다: 모델 불러오기(CPU·GPU), 얼굴 없는 합성 캔버스 스트림으로 추론 루프, 실패 이유 표시, 보고서 내보내기.
- **실제 얼굴 입력이 한 번도 들어가지 않았습니다.** 행렬 분해·박스·픽스처 경로는 실기기에서 처음 돕니다.
- 행렬 배치(열/행 우선)는 가정하지 않고 판별합니다.
  하지만 yaw·pitch·roll 부호(`src/core/matrix.ts` 의 `*_SIGN`)와 폰 롤 부호는 [추론]입니다. D1 자세 픽스처로 확정합니다.
- CSP 는 `connect-src` 만 강제하고 나머지는 관찰 모드입니다(아래). 사파리가 강제 헤더를 지키는지는 실기기에서 아직 확인하지 않았습니다.

### 네트워크 경계

**약속: 카메라 영상과 사진은 기기 밖으로 나가지 않습니다.**

앱 코드는 사진·영상·측정값을 네트워크로 보내지 않습니다.
다만 앱이 쓰는 라이브러리는 스스로 요청을 만들 수 있습니다.
그래서 약속은 "앱 코드가 보내지 않는다"가 아니라 "허용 목록 밖 요청을 막는다"로 지킵니다.

| 무엇 | 어디서, 어떻게 |
|---|---|
| 앱 본체 | 서버 없음. Next.js 정적 내보내기(`out/`)만 배포 |
| MediaPipe WASM | `@mediapipe/tasks-vision` 1.0.1 에서 빌드 때 `public/mediapipe/wasm/` 으로 복사해 **같은 출처**에서 제공(`scripts/copy-wasm.mjs`, 생성물이라 커밋 안 함) |
| 얼굴 모델(`face_landmarker.task`) | 재배포 조건이 불명확해 커밋하지 않고 **Google 서버**(`storage.googleapis.com`)에서 받음. 이때 기기 IP 가 Google 로 전달됨 |
| MediaPipe 사용 통계 | 라이브러리가 보내려 함. 앱이 **보내기 전에 막음**(아래) |
| 사진이 기기를 떠나는 길 | 사용자가 누르는 공유·다운로드뿐. 그 뒤(사진 앱, 클라우드 동기화, 메신저)는 앱이 통제 못 함 |

**MediaPipe 사용 통계**

- `@mediapipe/tasks-vision` 1.0.1 은 얼굴 모델 엔진을 만들 때마다 사용 통계 로거를 만듭니다.
- 60초마다, 그리고 엔진을 닫을 때 `https://odml.pa.googleapis.com/v1/log` 로 POST 합니다.
- 내용은 플랫폼·라이브러리 버전·과제 종류·실행 모드·초기화/추론 시간입니다. 끄는 옵션은 없습니다. 사진·영상은 들어가지 않습니다(패키지 README).
- 패키지 README 의 Privacy Notice 는 이 전송을 알리고 동의를 받을 책임을 앱 개발자에게 둡니다.
- 막는 방법은 두 겹입니다.
  - 배포본: 강제 CSP `connect-src 'self' https://storage.googleapis.com/mediapipe-models/`
  - 모든 환경(헤더 없는 `npm run dev` 포함): `src/spike/netguard.ts` 의 fetch 가드
- 막힌 횟수는 점검 페이지 11번에 남습니다.

**이 약속은 아직 실기기 네트워크 기록으로 확인하지 않았습니다.**
확인은 아이폰을 맥에 연결한 사파리 웹 인스펙터의 네트워크 기록으로 합니다.
기준은 허용 목록 밖 요청, `odml.pa.googleapis.com` 요청, POST/PUT 이 모두 0건인 것입니다.
점검 페이지 11번의 출처 목록(Resource Timing)과 가드 기록은 보조 자료이지 증명이 아닙니다.

### CSP: connect-src 만 강제, 나머지는 관찰(Report-Only)

`vercel.json` 은 모든 경로에 아래 헤더를 붙입니다.

**`Content-Security-Policy`(강제)**

```
connect-src 'self' https://storage.googleapis.com/mediapipe-models/; form-action 'none'; base-uri 'self'; frame-ancestors 'none'
```

- 허용 목록 밖으로 가는 fetch(MediaPipe 사용 통계 등)를 브라우저가 보내기 전에 막습니다.
- 원격은 호스트 전체가 아니라 **모델 버킷 경로**까지만 엽니다. `storage.googleapis.com` 은 누구의 버킷에든 업로드를 받는 호스트라, 통째로 열면 경계가 되지 않습니다.
- 이 지시어들은 점검 대상(WASM·GPU 위임·카메라 스트림·공유 시트)을 막지 않습니다. 크로미움에서 모델·WASM 로드를 확인했고, 아이폰 사파리는 D1 에서 확인합니다.

**`Referrer-Policy: no-referrer`**

모델 파일을 받을 때 배포 주소를 Google 에 넘기지 않습니다. IP 는 여전히 전달됩니다.

**`Content-Security-Policy-Report-Only`(관찰)**

- TECH-NOTES 1절 F10 이 요구하는 `connect-src`·`img-src`·`form-action` 에 `default-src`·`script-src 'wasm-unsafe-eval'`·`worker-src`·`media-src`·`base-uri`·`frame-ancestors` 를 더한 초안입니다.
- 더한 지시어의 근거는 문서가 아니라 구현 중 판단입니다.

**나머지를 관찰로 둔 이유**

- 아이폰 사파리에서 MediaPipe WASM·GPU 위임·카메라 스트림·공유 시트가 이 정책 아래에서 무엇을 요구하는지 **아직 한 번도 확인하지 못했습니다.**
