# 같은각도 — 세부 설명

README 에 다 담지 못한 설명입니다. 설계는 [PRD.md](PRD.md)(v0.3), 조사·실험 세부는 [TECH-NOTES.md](TECH-NOTES.md)(v0.2 기준이라 이전 방향의 내용이 섞여 있습니다)에 있습니다.

**2026-10-02 에 방향을 바꿨습니다.** 찍는 동안 안내해서 맞추게 하는 도구에서, 찍어 둔 동영상에서 기준 사진과 가장 가까운 장면을 골라 기울기·크기·위치를 맞춰 주는 도구로 바꿨습니다. 찍는 순간에 사람이 같은 각도·같은 크기를 맞추기가 어렵기 때문입니다. 이전 방향의 설계는 PRD 부록 A 에 접어 두었고, 그때 만든 아이폰 점검 페이지(`/spike/`)는 그대로 있습니다.

**이 문서의 새 방향은 실제 얼굴 사진·동영상으로 아직 한 번도 검증하지 않았습니다.**

## 1. 쓰임새

### 어떤 사진에 쓰나

| 사진 | 지금 |
|---|---|
| 정면 | 다룹니다 |
| 정면 숙임(헤어라인), 좌·우 사선 | 고를 수는 있지만 조건부입니다. 그 각도에서 얼굴 모델이 안정적으로 재는지 아직 확인하지 못했습니다 |
| 정수리, 뒤통수, 옆머리(90°), 수술 직후 가까이 찍는 사진 | 범위 밖입니다. 얼굴이 보이지 않으면 "각도를 잴 수 없음"으로 멈춥니다 |

한 번에 사진 한 쌍(기준 사진 1장 + 동영상 1개)만 다룹니다. 한 방문의 여러 사진을 이어서 처리하는 흐름은 없습니다.

### 고른 뒤에 맞출 수 있는 것과 없는 것

| | 고른 뒤에 | 그래도 남는 차이 |
|---|---|---|
| 기울기(화면 안에서 도는 것) | 회전으로 맞춥니다 | 거의 없습니다 |
| 얼굴 크기 | 확대·축소로 맞춥니다 | 찍은 거리가 달랐다면 원근은 그대로 다릅니다 |
| 화면 속 위치 | 이동으로 맞춥니다 | 얼굴이 화면의 다른 자리에 있었다면 카메라가 본 방향이 그만큼 다릅니다. 이 차이는 각도 차에 넣어 셉니다 |
| 좌우·위아래 각도 | 맞추지 못합니다 | 얼마나 다른지 숫자로 말합니다 |

### 믿을 수 있게 하는 장치

- **사진과 동영상은 서버로 보내지 않습니다.** 서버가 없습니다. 허용한 곳 말고는 인터넷 요청을 막는 규칙을 코드에 넣었습니다.
  - 단, 처음 켤 때 얼굴 위치를 찾는 파일(약 3.6MB)을 Google 서버에서 받습니다. 이때 기기의 인터넷 주소(IP)가 Google 에 전달됩니다.
  - 아이폰에서 실제로 막히는지는 아직 확인 전입니다.
- **가까운 장면이 없으면 없다고 말합니다.** 각도 차가 통과 기준(3°, 초깃값)을 넘으면 "가장 가까운 장면은 N° 차이 — 다시 찍기 권장"을 먼저 보이고, 그 장면에는 어디에서도 "가까운 장면"이라는 말을 붙이지 않습니다. 저장은 되지만 사유를 골라야 하고, 사진 아래 띠와 기록에 표시가 남습니다.
- **장면에 없던 것을 만들지 않습니다.** 회전·균등 확대·이동만 합니다. 빈 곳은 채우지 않고 회색으로 둡니다. 원본 장면을 함께 저장합니다.
- **같은 입력이면 같은 결과가 나옵니다.** 정해 둔 규칙으로 고르고, 판정에 쓴 숫자와 그때의 기준값이 기록 파일에 들어가서 나중에 다시 판정해 볼 수 있습니다.

### 아직 아닌 것

- **실제 얼굴 사진·동영상으로 한 번도 돌려 보지 않았습니다.** 얼굴 모델이 동영상 장면에서 방향을 얼마나 고르게 재는지, 3° 안의 장면이 동영상에 실제로 있는지, 고른 결과가 사람 눈에도 가까워 보이는지 모릅니다.
- **아이폰에서 아직 한 번도 돌려 보지 않았습니다.** 아이폰이 웹 페이지에 넘겨주는 동영상의 해상도·회전·형식부터 확인해야 합니다(PRD 4절 순서 ⓪).
- **병원 현장에서 써 보지 않았습니다.** 사용자는 가정한 사람입니다.
- **통과 기준과 그 밖의 숫자는 전부 초깃값입니다.** 실제 동영상으로 잡음을 재 본 뒤 정합니다.
- **다시 찍을 방향을 말해 주지 못합니다.** 각도 부호를 실제 기기로 확정하기 전이라, 얼마나 빗나갔는지만 그림으로 보입니다.

모발·두피 상태나 치료 효과는 판단하지 않습니다. 찍는 조건만 다룹니다. 의료기기로 허가받은 제품도 아닙니다.

### 다음에 확인할 것

1. **제 얼굴 동영상으로 로컬 검증.** 잡음 바닥, 같은 자세 반복, 사람이 고른 장면과의 비교(PRD 7절). 사진·동영상은 저장소에 넣지 않고 숫자만 남깁니다. 순서는 아래 "[실제 얼굴 동영상으로 확인하는 순서](#실제-얼굴-동영상으로-확인하는-순서아직-안-함)"에 있습니다.
2. **아이폰이 넘겨주는 동영상 확인.** 사진 보관함·파일 앱·바로 찍기 세 경로의 해상도·회전·권한 창.
3. **밖으로 나가는 요청이 정말 없는지 보기.** 아이폰을 맥에 연결해, 허용하지 않은 인터넷 요청이 0건인지 기록으로 확인합니다.
4. **통과 기준과 경고 경계 정하기.** 아래 "알려진 문제"의 세 경고부터 봅니다.

### 누가 만들었나

- 설계 문서와 코드의 초안은 AI 코딩 도구(Claude Code)가 썼습니다.
- 동영상에서 고르는 쪽으로 방향을 바꾼 것은 제가 정했습니다. 무엇을 채택할지와 통과 기준 확정도 제 몫입니다.
- 자세한 역할 나눔과 AI 가 틀렸던 지점은 [설계 문서](PRD.md) 8절에 있습니다.

## 2. 고르는 화면(`/pick/`)

카메라 권한을 묻지 않습니다. 파일만 받습니다.

### 화면 흐름

| 단계 | 하는 일 | 화면에 보이는 것 |
|---|---|---|
| ① 기준 사진 | 사진 종류(정면·정면 숙임·왼쪽 사선·오른쪽 사선)를 고르고 사진 1장을 고릅니다 | 얼굴을 찾았는지, 사진 크기, "이 환자의 사진이 맞는지 확인해 주세요" |
| ② 동영상 | 동영상을 고르거나 "지금 바로 찍기"(폰의 카메라 앱이 찍어서 넘겨줌) | 고른 사진 종류에 맞는 찍는 방법, 찍기 전 확인, 카메라 설정, 찍은 동영상이 폰에 남는다는 안내 |
| ③ 분석 | 전체를 초당 2장으로 훑고 → 가까운 구간만 촘촘히 → 고른 장면을 다시 잽니다 | 받은 동영상의 해상도·길이, "몇 장면 중 몇 장면", 먼저 나오는 답("근처를 지나갔는지"), 취소, 화면을 켜 두라는 안내 |
| ④ 결과·저장 | 기준 사진과 고른 장면을 나란히 또는 겹쳐(진하기 조절) 봅니다. 맞춘 것/원본 장면을 바꿔 봅니다. 후보 작은 그림을 눌러 바꿉니다(보는 방법은 그대로 남습니다). 맨 아래에서 메모(선택)를 적고 파일을 만든 뒤 하나씩 받습니다 | 위에서부터: 판정과 각도 차 → 경고(3개까지 펼침) → 사진 → 차이 숫자 다섯 줄(각도 차, 맞춘 기울기, 얼굴 크기 차, 늘려 그린 배율, 위치 차) → 후보 → 늘 보이는 문장 세 줄 → 나머지 숫자(접힘) → 동영상이 지나간 방향 그림 → 저장(보정본 PNG, 원본 장면 PNG, 기록 JSON) |

가까운 장면이 없으면 ④에서 사진을 보이기 전에 다시 찍기를 먼저 권하고, "그래도 가장 가까운 장면 보기"를 눌러야 사진과 저장이 열립니다. 다시 찍은 횟수를 세고(끝까지 간 분석만), 통과 기준을 넘는 장면을 저장하려면 사유(자세 유지가 어려움·시간 부족·기타)를 골라야 합니다. 다시 찍기는 두 번까지만 권합니다. 두 번을 채우면 첫 화면의 문장이 "더 찍지 않아도 됩니다"로, 첫 버튼이 "가장 가까운 장면 보고 저장하기"로 바뀝니다. 저장을 막지는 않습니다.

분석 중이거나 결과가 떠 있을 때 새로 고치거나 창을 닫거나 "같은각도 처음으로"를 누르면 떠날지 한 번 묻습니다. 분석 결과와 저장 전 파일은 기기 메모리에만 있어서 떠나면 사라집니다.

### 멈추는 경우와 화면의 문장

| 경우 | 문장 |
|---|---|
| 기준 사진에서 얼굴을 찾지 못함(정수리 등) | 이 사진에서는 얼굴이 보이지 않아 각도를 잴 수 없습니다. 얼굴이 보이는 사진을 골라 주세요. |
| 기준 사진에 얼굴이 둘 이상 | 한 사람만 나온 사진을 골라 주세요. |
| 기준 사진 파일을 열 수 없음 | 이 사진은 이 브라우저에서 열 수 없습니다. 찍은 폰에서 열거나 JPEG로 저장해 주세요. |
| 동영상을 열 수 없음 | 이 동영상은 이 브라우저에서 열 수 없습니다. 찍은 폰에서 열거나 다른 형식으로 찍어 주세요. |
| 쓸 수 있는 장면이 없음 | 쓸 수 있는 장면이 없습니다(얼굴 없음 ○장, 얼굴이 둘 이상 ○장, 잘림·작음 ○장, 흔들림 ○장, 노출 ○장). 다시 찍어 주세요. — 0장인 사유는 적지 않습니다. 얼굴이 둘 이상 잡힌 장면이 있으면 "뒤에 선 사람, 거울, 포스터가 화면에 들어오지 않게 찍어 주세요"가 붙습니다 |
| 얼굴을 찾는 프로그램을 받지 못함 | 얼굴을 찾는 프로그램을 받지 못했습니다. 인터넷 연결을 확인하고 다시 해 주세요. |
| 그 밖 | 알 수 없는 문제로 멈췄습니다. 처음부터 다시 해 주세요. |

위 다섯 줄은 엔진의 문장(`src/pick/messages.ts`)을 그대로 씁니다. 개발자용 원문(오류 원문, 얼굴 모델을 받는 동안의 진행 문장)은 화면에서 접혀 있습니다. 방향을 말하는 문장("고개를 더 왼쪽으로")은 없습니다.

### 저장 파일

- 이름: `같은각도_정면_20261002-1430_메모_보정본.png`, `…_원본장면.png`, `…_기록.json`. 메모는 경로·예약 문자를 빼고 24자까지 붙습니다.
- 두 PNG 는 사진 **아래에 덧붙인 띠**에 "내부 기록용 · 광고·홍보 사용 금지", 보정 여부, 사진 종류·날짜가 들어갑니다. 통과 기준을 넘는 장면이면 "가까운 장면 없음 · 각도 차 N°"도 들어갑니다. 띠는 사진 영역을 가리지 않습니다. 잘라내면 사라지는 표시라서, 같은 사실이 기록에도 남습니다.
- 기록 JSON 에는 판정에 쓴 숫자, 보정량, 뺀 장면 수, 고른 순위(도구가 고른 1등인지 사람이 바꾼 후보인지), 다시 찍은 횟수와 사유, 메모, 두 PNG 와 기준 사진 파일의 SHA-256, 규칙 값 전부가 들어갑니다. 이미지·얼굴 점 좌표는 들어가지 않습니다(PRD 5절 "기록에 남는 것").
- 원본 장면이 기준이 되는 사진이고 보정본은 견주어 보려고 만든 파생본이라는 것이 이 도구의 권고입니다. 무엇을 차트에 넣을지는 병원이 정합니다.
- 찍은 동영상은 소리와 함께 폰에 남습니다. 웹 페이지는 그 파일을 지울 수 없습니다.

| 위치 | 내용 |
|---|---|

| `src/pick/glue/` | 엔진과 브라우저를 잇는 곳: 얼굴 모델, 동영상 탐색, 재는 캔버스, 보정본 그리기 |

| `src/pick/screen/session.ts` | 접착부: 브라우저가 하는 일을 밖에서 받아 흐름을 돌림. 시험에서는 가짜를 넣음 |
| `src/pick/screen/browser.ts` | 그 "브라우저가 하는 일"의 진짜 구현(그림, PNG 띠, 해시) |
| `src/pick/screen/parts.tsx`, `PickApp.tsx` | 화면 조각과 껍데기 |
| `src/pick/screen/guide.ts` | 찍는 방법 문장(PRD 3절·6절과 같은지 시험이 확인) |

### 확인한 것

전부 합성 데이터와 코드로 그린 얼굴 그림으로 한 확인입니다. 실제 얼굴에서 쓸 만한지는 말해 주지 않습니다.

- **자동 시험 749개**(`npm run verify`, 2026-10-02). 고르기 엔진 262 + 엔진과 브라우저를 잇는 곳 6 + 화면 231 + 이전부터 있던 측정 함수·점검 페이지·CSP 250.
- **화면 시험이 넣는 것은 가짜 측정값입니다.** 얼굴 모델·동영상·캔버스 자리에 가짜를 넣고, 분석은 진짜 엔진을 돌려 흐름 전체(기준 사진 → 동영상 → 분석 → 후보 바꾸기 → 저장)를 봅니다. 화면 조각은 노드에서 문자열로 그려 무엇이 보이고 안 보이는지만 봅니다.
- **규칙 문서만 보고 따로 쓴 계산과 견주기(200개).** 설계 문서 5절만 읽고 파이썬으로 따로 짠 계산과 엔진에 같은 합성 장면 200묶음을 넣어 결과를 견줬습니다.
  - 1등 장면, 가까움 판정, 멈춤, 변환 행렬, 제외 수는 처음부터 200개 모두 같았습니다.
  - 처음에는 183개만 전부 같았습니다. 15개는 엔진의 결함이었습니다. "0.3초 이상 떨어진 장면"을 셈할 때 2.8 − 2.5 가 컴퓨터 안에서 0.2999…로 나와, 정확히 0.3초 떨어진 차점 후보가 빠지거나 들어갔습니다(1등은 그대로, 3개에서는 3° 안의 후보 대신 3° 밖 장면이 들어감). 시각 간격을 100만분의 1초의 허용오차로 견주게 고쳤고, 고친 뒤 198개가 같습니다.
  - 나머지 2개는 문서가 정하지 않은 경우였습니다(촘촘히 훑을 곳을 고를 때 각도 차가 똑같은 두 장면). 엔진의 순서(각도 차 → 점수 → 이른 시각)를 문서에 적었고, 따로 쓴 계산도 그 문장대로 고치면 200개가 같습니다.
  - 이 대조는 측정값에서 시작합니다. 얼굴 점에서 측정값을 만드는 단계, 실제 픽셀을 옮겨 그리는 단계, 브라우저 쪽은 대상이 아니었습니다.
- **일부러 결함을 넣어 보기(변이 시험).** 결함을 하나씩 넣고 시험이 실패하는지 봤습니다.
  - 처음에는 149개 가운데 127개만 잡혔습니다. 살아남은 22개 중 20개는 시험의 구멍이었고(엔진과 브라우저를 잇는 곳에는 시험이 아예 없었습니다), 시험 20개를 더해 잡았습니다. 가장 실질적인 구멍은 기준 사진의 긴 변이 960px보다 작을 때 보정본 크기가 틀어지는 결함을 못 잡던 것입니다(코드는 맞았고 시험이 없었습니다).
  - 이번에 고친 곳에 넣은 16개를 더해 지금은 165개 가운데 162개를 잡습니다. 남은 3개는 결과가 같아서 잡을 수 없는 변이로 봅니다(먼저 걸러져 닿지 않는 검사를 뺀 것, 같은 장면을 캔버스 대신 동영상에서 그린 것, 같은 일을 하는 안전장치 둘 중 하나를 뺀 것). 둘째 것은 실제 브라우저에서만 확인할 수 있습니다.
  - 이와 따로 화면 쪽 변이 29종도 봤습니다. 25종이 잡혔고, 살아남은 4종 중 3종은 시험을 더해 잡았고, 1종은 결과가 같은 변이입니다.
  - 잡은 수는 넣어 본 결함에 대한 것일 뿐, 넣어 보지 않은 결함은 말해 주지 않습니다.
- **맥의 헤드리스 크롬에서 돌려 본 것**(미리보기 서버, 강제 CSP 포함, 390×844와 1280×800). 코드로 그린 얼굴 그림(사람 사진 아님)을 기준 사진으로, 그 그림을 기울이고 옮겨 만든 8초 동영상(H.264, 1080×1440)을 넣었습니다.
  - 실제 얼굴 모델이 그린 얼굴을 찾았고, 분석이 끝까지 갔고, 보정본이 기준 사진과 겹쳤습니다(README 화면 ②③).
  - 걸린 시간은 먼저 나오는 답까지 약 1초(1회), 결과 화면이 뜰 때까지 약 3초(2회)였습니다. 얼굴 모델을 이미 받아 둔 상태의 맥이고, 폰의 속도는 모릅니다.
  - 요청은 자기 출처, 얼굴 모델 파일 1개, 기기 안 그림(`blob:`)뿐이었고 CSP 위반은 0건이었습니다(이 실행들에서).
  - 가짜 측정값을 넣어 확인한 것: 얼굴이 둘씩 잡히는 동영상의 멈춤 문장, 가까운 장면 없음과 다시 찍기 두 번 뒤의 화면, 세로 사진에 가로 동영상을 넣었을 때 경고가 사진보다 위에 나오는 것, 후보를 바꿔도 겹쳐 보기가 유지되는 것, 떠날 때 묻는 창.
  - 화면 점검에서 나온 문제 16건(중간 4, 낮음 12) 가운데 14건을 고쳤고, 2건은 일부만 고쳤습니다(아래 "알려진 문제" 4·5번).
- 엔진의 합성 시험 결과(시드 1,000개): 고르기 오차의 95번째 백분위 0.83°(장면에만 잡음)·1.33°(기준에도 잡음), 나쁜 장면을 고른 수 0, 3.5° 이상 묶음에서 "가까운 장면"으로 표시한 수 0.

### 확인하지 못한 것

- **실제 얼굴.** 그린 얼굴 그림은 평평해서, 동영상에서 실제로 바뀐 것은 기울기·크기·위치뿐입니다. 좌우·위아래 각도가 바뀌는 진짜 고개 움직임은 한 번도 넣어 보지 못했습니다.
- **아이폰 사파리 전부.** 재생 전에 장면을 푸는지, 탐색이 요청한 시각의 장면을 돌려주는지, 세로 동영상의 회전, HEIC·HEVC, "지금 바로 찍기"가 권한 창을 띄우는지, 저장 링크(`<a download>`)가 어떻게 동작하는지, 큰 동영상에서 메모리가 버티는지, 떠날 때 묻는 창이 뜨는지.
- **화면 꺼짐 방지.** 분석 중 화면이 꺼지지 않게 브라우저에 부탁하지만(Wake Lock), 아이폰에서 되는지 확인하지 못했습니다. 그래서 안내 문장을 함께 보입니다.
- **390px 폰에서의 실제 손맛.** 화면 사진은 헤드리스 크롬의 390px 폭으로 찍었습니다.
- **기준점 번호.** 얼굴 메시의 점 번호는 기억으로 옮긴 값입니다. 그린 얼굴에서는 보정본이 겹쳤지만, 실제 얼굴에서 그 자리에 찍히는지는 확인 전입니다.
- **동영상을 여는 중의 취소.** 자동 시험으로만 봤습니다. 브라우저에서 "여는 중"이 길게 이어지는 파일을 만들지 못해 직접 눌러 보지 못했습니다.

### 실제 얼굴 동영상으로 확인하는 순서(아직 안 함)

제 얼굴 사진과 동영상으로 로컬에서 합니다. 파일은 저장소 폴더 밖에 두고 커밋하지 않습니다. 남기는 것은 숫자뿐입니다.

```sh
npm install
npm run build        # 또는 npm run verify
npm run preview      # http://localhost:3100/pick/ — 배포와 같은 CSP 헤더가 붙습니다
```

준비물: 정면 사진 1장(JPEG), 폰 기본 카메라로 찍은 10~15초 동영상(1080p, HDR 끔, "높은 호환성" 형식, 사진과 같은 세로 방향, 기준 자세로 3초 멈춘 뒤 좌우·위아래로 천천히). 그리고 폰을 고정하고 가만히 있는 5초 동영상 1개.

| 순서 | 볼 것 | 왜 |
|---|---|---|
| 1 | 기준 사진에서 "얼굴을 찾았습니다"가 뜨고, 사진 크기가 실제와 같은가 | 사진의 회전 정보를 반영해 읽는지 |
| 2 | 분석 화면의 "받은 동영상" 해상도·길이가 실제와 같은가. 걸린 시간 | 세로 동영상이 가로로 읽히지 않는지 |
| 3 | 고른 장면이 눈으로 봐도 가장 가까운가. 직접 고른 장면과 몇 초 차이인가 | 고르는 규칙이 쓸 만한지(PRD 7절) |
| 4 | 겹쳐 보기에서 눈·코가 기준 사진과 겹치는가. 좌우가 뒤집혀 보이지 않는가 | 기준점 번호와 변환 방향 |
| 5 | "동영상이 지나간 방향" 그림이 십자 모양인가. 고개를 오른쪽으로 돌린 구간의 점이 어느 쪽에 찍히는가 | 보는 방향 계산, 각도 부호를 정할 재료 |
| 6 | 가만히 있는 5초 동영상에서 점들이 얼마나 퍼지는가(기록 JSON 의 자취 값으로 계산) | 잡음 바닥. 1°를 넘으면 통과 기준 3°를 다시 정해야 합니다 |
| 7 | 같은 동영상을 두 번 넣으면 같은 장면·같은 숫자가 나오는가. "다시 뽑았더니 값이 달라졌습니다"가 뜨는가 | 장면 뽑기가 같은 장면을 돌려주는지 |
| 8 | 경고가 맞는 말인가. 특히 "크기가 N배", "N배 늘려 그렸습니다" | 아래 "알려진 문제" 1·3번 |
| 9 | 저장한 세 파일: 띠의 문구, 기록 JSON 에 사진·얼굴 점 좌표가 없는가 | 저장 규칙 |
| 10 | 개발자 도구의 네트워크 기록에 자기 출처, 얼굴 모델 파일 1개, `blob:` 말고 다른 요청이 없는가 | 네트워크 약속 |

그다음에 아이폰 사파리에서 같은 순서를 배포 주소(HTTPS)로 한 번 더 합니다.

### 알려진 문제(확정 전)

화면은 엔진이 낸 경고를 그대로 보입니다. 아래 셋은 규칙을 다시 봐야 합니다.

1. "얼굴이 화면에서 차지하는 크기가 N배" 경고가 3:4 사진과 9:16 동영상 조합에서 늘 뜹니다(짧은 변으로 나누기 때문).
2. "다시 뽑았더니 값이 달라졌습니다" 경고가 잡음만으로 자주 뜹니다(합성 잡음 σ 0.5°에서 1등의 16~19%).
3. "N배 늘려 그렸습니다" 경고가 동영상 해상도가 낮으면 같은 장면에서도 뜹니다.

화면 쪽에 남은 것입니다.

4. 브라우저의 뒤로 가기로 떠날 때는 묻지 않습니다(새로 고침, 창 닫기, "같은각도 처음으로"만 묻습니다).
5. 결과 화면이 깁니다(390px 폭에서 전체 약 2,900px이고 저장은 맨 아래). 위쪽에 "저장으로 가기" 링크를 뒀을 뿐입니다.
6. 다시 잰 장면 네 장이 모두 버려지면 그다음 순위를 찾지 않고 "쓸 수 있는 장면이 없습니다"로 멈춥니다. 이때 문장에 사유가 붙지 않습니다.

### D1 실기기 점검 페이지(`/spike/`)

아이폰 사파리에서 카메라·얼굴 모델·센서·공유가 실제로 어떻게 동작하는지 재는 개발용 페이지입니다.
TECH-NOTES 6절 체크리스트를 섹션 0~11로 나눴고, 섹션마다 해당 항목 번호가 적혀 있습니다.
점검 섹션은 12개(0~11번)이고, 12번은 점검 항목이 아니라 결과 내보내기 화면입니다. 앱이 인터넷에서 받는 외부 파일은 얼굴 모델 1개(약 3.6MB)입니다.

**1. HTTPS 로 엽니다.**
아이폰 카메라는 보안 컨텍스트에서만 열립니다. LAN 의 http 개발 서버로는 안 되고, HTTPS 로 배포한 주소의 `/spike/` 를 엽니다.

**2. 시작 전 준비**

- 자동 잠금 '안 함', 저전력 모드 끔.
- 무음 모드 해제, 볼륨 올림. 기록·카운트다운의 시작과 끝을 삐 소리로 알립니다.
- 0번 [소리 시험]으로 소리가 나는지 먼저 봅니다.
- 사파리 16.4+ 는 오디오 세션을 playback 으로 둡니다. 무음 스위치와 상관없이 소리가 나고, 그 상태를 0번에 적습니다.

**3. 위에서부터 차례로**

1. 환경·소리 시험
2. [카메라 켜기] → [모델 불러오기] → [추론 시작] → [지금 성능 저장]
3. 흔들림 30초 기록
4. 자세 6개
5. 같은 프레임 비교, takePhoto 비교
6. **12번에서 중간 내보내기 한 번**(7·10번은 사파리를 떠납니다)
7. 옛 사진 1장, 동작 센서, 픽셀 비용, 공유 시험, 네트워크 출처

**4. 결과 보내기**

- 결과는 이 기기에 임시 저장됩니다. 탭이 다시 열려도 복원됩니다.
- 마지막 12번에서 [복사](가장 빠름)·[파일로 저장]·[공유] 중 하나로 `same-angle-d1-report-YYYYMMDD-HHmm.json` 을 내보내 개발자에게 보냅니다.
- 개발자는 이 JSON 을 Claude Code 대화에 붙여 넣어 함께 읽습니다.

자세한 순서·완료 조건·내보내기는 TECH-NOTES 10절에 있습니다.

**결과 JSON 에 들어가지 않는 것**

JSON 에는 이미지와 얼굴 랜드마크 좌표가 들어가지 않습니다.
들어가는 것은 기기 정보(userAgent·화면 크기·DPR), 측정 숫자, 자세 픽스처의 행렬 16개 숫자뿐입니다.

내보내기 전에 검사기(`src/core/report.ts`)가 다음을 거부합니다.

- 이미지·랜드마크 키, `data:` URL, base64 로 보이는 긴 연속 문자
- 긴 문자열·배열, 비유한 수
- 섹션마다 수 900개·글자 24,000자를 넘는 총량(여러 조각으로 쪼개 넣어도 걸림)

총량 한도는 통째로 넣는 것을 막을 뿐, 몇 점까지 막는다는 증명은 아닙니다.
나머지는 "섹션 데이터에는 이름 붙인 요약 숫자만" 넣는 점검 페이지 코드가 맡습니다.

### 점검 페이지에서 아직 검증하지 않은 것

- **점검 페이지를 아이폰에서 아직 돌려 보지 않았습니다.**
  카메라 없는 맥의 크로미움 계열 브라우저에서 다음까지만 확인했습니다: 모델 불러오기(CPU·GPU), 얼굴 없는 합성 캔버스 스트림으로 추론 루프, 실패 이유 표시, 보고서 내보내기.
- **실제 얼굴 입력이 한 번도 들어가지 않았습니다.** 행렬 분해·박스·픽스처 경로는 실기기에서 처음 돕니다.
- 행렬 배치(열/행 우선)는 가정하지 않고 판별합니다.
  하지만 yaw·pitch·roll 부호(`src/core/matrix.ts` 의 `*_SIGN`)와 폰 롤 부호는 [추론]입니다. D1 자세 픽스처로 확정합니다.

### 네트워크 경계

**약속: 카메라 영상, 사진, 동영상은 기기 밖으로 나가지 않습니다.**

앱 코드는 사진·영상·측정값을 네트워크로 보내지 않습니다.
다만 앱이 쓰는 라이브러리는 스스로 요청을 만들 수 있습니다.
그래서 약속은 "앱 코드가 보내지 않는다"가 아니라 "허용 목록 밖 요청을 막는다"로 지킵니다.

| 무엇 | 어디서, 어떻게 |
|---|---|
| 앱 본체 | 서버 없음. Next.js 정적 내보내기(`out/`)만 배포 |
| MediaPipe WASM | `@mediapipe/tasks-vision` 1.0.1 에서 빌드 때 `public/mediapipe/wasm/` 으로 복사해 **같은 출처**에서 제공(`scripts/copy-wasm.mjs`, 생성물이라 커밋 안 함) |
| 얼굴 모델(`face_landmarker.task`) | 재배포 조건이 불명확해 커밋하지 않고 **Google 서버**(`storage.googleapis.com`)에서 받음. 이때 기기 IP 가 Google 로 전달됨 |
| MediaPipe 사용 통계 | 라이브러리가 보내려 함. 앱이 **보내기 전에 막음**(아래) |
| 고르는 화면(`/pick/`)이 읽는 파일 | 고른 사진은 `createImageBitmap`, 동영상은 `<video src=blob:>` 로만 읽음. `fetch` 로 읽지 않음(가드와 CSP 가 `blob:` 의 fetch 도 막음). 해시는 기기 안에서 계산 |
| 사진이 기기를 떠나는 길 | 사용자가 누르는 공유·다운로드뿐. 그 뒤(사진 앱, 클라우드 동기화, 메신저)는 앱이 통제 못 함 |

**MediaPipe 사용 통계**

- `@mediapipe/tasks-vision` 1.0.1 은 얼굴 모델 엔진을 만들 때마다 사용 통계 로거를 만듭니다.
- 60초마다, 그리고 엔진을 닫을 때 `https://odml.pa.googleapis.com/v1/log` 로 POST 합니다.
- 내용은 플랫폼·라이브러리 버전·과제 종류·실행 모드·초기화/추론 시간입니다. 끄는 옵션은 없습니다. 사진·영상은 들어가지 않습니다(패키지 README).

- 막는 방법은 두 겹입니다.
  - 배포본: 강제 CSP `connect-src 'self' https://storage.googleapis.com/mediapipe-models/`
  - 모든 환경(헤더 없는 `npm run dev` 포함): `src/spike/netguard.ts` 의 fetch 가드

- 고르는 화면(`/pick/`)은 화면이 뜨자마자 같은 fetch 가드를 깝니다. 이 화면이 새로 더한 외부 요청은 없고, `src/pick` 의 소스에 네트워크 호출이 적혀 있지 않은지 시험(`src/pick/screen/network.test.ts`)이 확인합니다.

### CSP: connect-src 만 강제, 나머지는 관찰(Report-Only)

`vercel.json` 은 모든 경로에 아래 헤더를 붙입니다.

**`Content-Security-Policy`(강제)**

```
connect-src 'self' https://storage.googleapis.com/mediapipe-models/; form-action 'none'; base-uri 'self'; frame-ancestors 'none'
```

- 허용 목록 밖으로 가는 fetch(MediaPipe 사용 통계 등)를 브라우저가 보내기 전에 막습니다.
- 원격은 호스트 전체가 아니라 **모델 버킷 경로**까지만 엽니다. `storage.googleapis.com` 은 누구의 버킷에든 업로드를 받는 호스트라, 통째로 열면 경계가 되지 않습니다.
- 이 지시어들은 점검 대상(WASM·GPU 위임·카메라 스트림·공유 시트)을 막지 않습니다. 크로미움에서 모델·WASM 로드를 확인했고, 아이폰 사파리는 D1 에서 확인합니다.

**`Referrer-Policy: no-referrer`**

모델 파일을 받을 때 배포 주소를 Google 에 넘기지 않습니다. IP 는 여전히 전달됩니다.

**`Content-Security-Policy-Report-Only`(관찰)**

- TECH-NOTES 1절 F10 이 요구하는 `connect-src`·`img-src`·`form-action` 에 `default-src`·`script-src 'wasm-unsafe-eval'`·`worker-src`·`media-src`·`base-uri`·`frame-ancestors` 를 더한 초안입니다.
- 더한 지시어의 근거는 문서가 아니라 구현 중 판단입니다.

**나머지를 관찰로 둔 이유**

- 아이폰 사파리에서 MediaPipe WASM·GPU 위임·카메라 스트림·공유 시트가 이 정책 아래에서 무엇을 요구하는지 **아직 한 번도 확인하지 못했습니다.**
- 처음부터 전부 강제하면 점검 자체가 막혀, 무엇이 모자랐는지 알 수 없습니다.
- Report-Only 에서도 브라우저는 위반마다 `securitypolicyviolation` 이벤트를 냅니다. 점검 단계에서 위반 목록을 모으고, 정책을 고친 뒤 강제로 바꿉니다(조건은 TECH-NOTES 10절).
- CSP 문자열은 `src/csp.test.ts` 가 고정합니다.
- 고르는 화면을 더하면서 **헤더는 바꾸지 않았습니다.** 강제 헤더는 `connect-src` 등 네 지시어뿐이라 `<video src=blob:>`·`<img src=blob:>`·`<a download href=blob:>` 를 막지 않고, 관찰 헤더의 `media-src`·`img-src` 에는 이미 `blob:` 이 있습니다. 시험에는 `/pick/` 경로에 헤더가 붙는지와, `blob:` 이 `connect-src` 에 들어가지 않았는지를 더했습니다.

`npm run preview` 는 `vercel.json` 의 헤더를 읽어 같은 헤더를 붙입니다. 그래서 로컬 미리보기와 배포의 CSP 동작이 같습니다. `npm run dev` 에는 헤더가 없습니다.
